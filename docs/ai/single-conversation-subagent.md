# single-conversation-subagent：单对话两级协作 Skill

本作品的**第二个自定义 Skill**，沉淀的不是产品知识，而是**开发方法本身**——「一个对话里
怎么让 AI 稳定地做工程」的协议。开发期一直用它跑本仓的板级/驱动/文档工作。

| 项 | 值 |
| --- | --- |
| 独立开源仓 | <https://github.com/jinsc123654/single-conversation-subagent-skill> |
| 版本 | **1.3.4**（2026-11-02；首版 2026-10-19） |
| 运行形态 | 用户级 Skill（`SKILL.md` + `references/protocol.md`），`install.sh` 一键装 |
| 与 `vela-helm-one` 的分工 | 本文管**怎么做**（流程/分工/验收）；`vela-helm-one` 管**做什么**（板级权威值与处置） |

## 它解决什么问题

单人 + AI 做 25 万行级别的工程，失控点不在"模型不够聪明"，而在四件事：

1. **上下文爆炸** —— 一个对话里塞进整棵树，AI 开始凭印象改代码；
2. **没有验收闭环** —— AI 说"改好了"，没人验；
3. **任务边界漂移** —— 让查个日志，顺手把构建脚本改了；
4. **过程不可复现** —— 换个会话，同样的坑从头再踩一遍。

## 协议要点

| 层 | 职责 |
| --- | --- |
| **主对话（协调者）** | 发现并定义问题、划范围与授权、拆分任务、创建并调度执行子 Agent、汇总证据、**独立验收**；维护阶段记忆 |
| **执行子 Agent** | 按任务命名，只做分析/实现/测试，返回**有界证据**，不再向下委派 |
| **外部只读审查者** | 主对话可另起 Codex 做独立复核（非子 Agent，子 Agent 不得启动它） |

四条硬机制：

- **一对话一问**：每个对话只在首个任务问一次「快速处理 / 标准执行 / 长任务 / 只调查」，
  后续沿用；标准与长任务再问一次验证范围（可选 Codex 联动），之后不再重复打断；
- **有界等待**：提问给推荐项 + 15 秒上限，超时按推荐继续，不无限阻塞；
- **证据落盘**：阶段记忆写在 `<docs-root>/agent/`（`AGENT_PROJECT.md`、`AGENT_COORDINATION.md`、
  `evidence/`），下个会话可直接续；
- **验收独立**：执行者不能给自己判决，验收结论由主对话重新取证。

## 在本作品里的实际效果

- **省上下文**：板级排查这类"读 20 个文件、只改 3 行"的活全部下沉给子 Agent，
  主对话只保留结论与证据路径；
- **防漂移**：只调查模式是只读的，查日志不会顺手改代码（本仓 `vela_override/` 与
  `docs/` 的改动因此都能追溯）；
- **可复现**：每次踩坑的原因与处置按固定格式留档，最后汇成 `vela-helm-one` 的
  `troubleshooting.md`（23 节）——**方法论 Skill 沉淀知识，知识 Skill 沉淀结论**。
