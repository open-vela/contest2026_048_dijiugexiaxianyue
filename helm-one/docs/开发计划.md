# 自行车码表 — 开发计划（开发板 + 面包板阶段）

> 目标产品：SF32LB527 + L96 + BMI270 + BMP388 + 2.4" MIP + 按键 + SD + USB/BLE  
> 本文档：从 **官方开发板 + 面包板验证** 到 **自研硬件** 的分阶段路线。  
> 更新日期：2026-05-30

---

## 1. 目标与原则

### 1.1 最终产品（V1 参考）

| 模块 | 选型 |
|------|------|
| 主控 | SF32LB527UD6（16M PSRAM，片内 PMU + 充电） |
| GNSS | Quectel L96-M33 + 外置天线（FPC/Patch） |
| 传感器 | BMI270、BMP388（I2C） |
| 显示 | 2.4" MIP，无触摸，2～3 实体按键 |
| 存储 | 外置 Nor16M（固件）+ microSD（地图/GPX/记录） |
| 连接 | USB-C（充/刷机）+ BLE（传感器/手机） |
| 时间 | 片内 RTC + GPS 校时（**无需** DS3231） |

### 1.2 原型阶段原则

1. **先跑通软件链路**，再抠电源与结构。  
2. 开发板尽量选与量产芯片 **同系列、同 SDK 工程**（PSRAM + 外置 Flash）。  
3. 面包板只验证 **UART / I2C / 供电**，高频信号（QSPI 屏）尽量用开发板已焊接 FPC。  
4. 每阶段有 **可演示里程碑**（能录屏、能Outdoor 测一圈）。

## 2. 推荐采购清单（第一阶段）

### 2.1 必买（核心）

| 物品 | 推荐型号 | 用途 |
|------|----------|------|
| 主开发板 | **SF32LB52-DevKit-LCD-1-N16R8** 或 **Nano-N16R16** | LCD-1：屏+TF+按键+充电，更接近码表；Nano：更小，需另接屏 |
| 调试线 | USB-C 数据线 | 供电、下载、串口 |
| GNSS 模块 | **Quectel L96** 开发板或 L96-M33 + IPEX 天线 | 建议带外置天线版本 |
| 气压计 | **BMP388** 模块（3.3V，I2C） | 海拔/爬升 |
| 加速度 | **BMI270** 模块（3.3V，I2C） | 自动暂停、姿态 |
| 面包板 + 杜邦线 | 830 孔板、公母线若干 | 传感器/GPS 临时接线 |
| USB-TTL（备用） | 若板子仅 USB 调试可省略 | 救急烧录 |

> **说明**：量产用 **527UD6（带充电）**；开发板多为 **JUD6 + 外置 Nor**，SDK/API 一致，**充电与 527 差异在阶段 4 再对齐**。

### 2.2 建议买（提升效率）

| 物品 | 用途 |
|------|------|
| 2.4" MIP 模组（或 LCD-1 套件自带屏） | UI；MIP 与量产一致 |
| microSD 卡 + 读卡器 | 地图/GPX 测试 |
| 常按按钮模块 ×3 | 翻页 / 开始暂停 / 背光 |
| 锂电池 3.7V + 保护板（可选） | LCD-1 板载充电时可配 450mAh 体验续航 |
| 户外测试支架 | 车把夹或近似结构 |

### 2.3 暂不需要

| 物品 | 原因 |
|------|------|
| DS3231 等外部 RTC | GPS + 片内 RTC 足够 |
| ETA9184 | 527 片内充电，原型板自带充电管理 |
| 电容触摸模块 | 方案已定 MIP + 按键 |
| OpenVela 开发板 | 与 SF32 路线不同，除非并行调研 |

## 4. 分阶段开发路线

```text
阶段1  平台点亮          周 1～2   LVGL + 按键 + 基础 UI
阶段2  传感器          周 2～3   I2C 气压/IMU + 显示
阶段3  GNSS            周 3～5   L96 UART + 速度/距离/轨迹
阶段4  存储与记录      周 5～7   SD 卡 + GPX/FIT + 骑行记录
阶段5  地图（可选）    周 7～10  离线瓦片或纯轨迹
阶段6  BLE             周 8～10  心率/踏频 + 手机同步
阶段7  电源与 527      周 10～12 充电/电量/休眠对齐量产
阶段8  自研 PCB        周 12+    原理图 → PCB → 结构
```

---

## 5. 阶段 1：平台点亮（第 1～2 周）

### 5.1 任务

- [ ] 在开发板上跑通 **LVGL** 官方或 SDK 例程  
- [ ] 实现 **2～3 个 GPIO 按键** 输入（消抖、短按/长按）  
- [ ] 搭简易 **多页面 UI 框架**：主页 / 数据页 / 设置页（空数据即可）  
- [ ] 背光：PWM 调光（若板子接 BL_PWM）  

### 5.2 面包板

本阶段 **可不用面包板**，仅用开发板自带屏和按键。

### 5.3 里程碑 M1

**标准**：按键切换页面、背光可调、UI 刷新流畅（录屏）。

---

## 6. 阶段 2：传感器（第 2～3 周）

### 6.1 接线（面包板）

| 模块 | 接口 | 说明 |
|------|------|------|
| BMP388 | I2C | 与 BMI270 **同总线**，不同地址 |
| BMI270 | I2C | 3.3V，勿接 5V |

从开发板 **3.3V + GND + I2C_SCL/SDA** 引出；线尽量短。

### 6.2 任务

- [ ] 读取 BMP388 气压 → 换算海拔（可相对校准）  
- [ ] 读取 BMI270 加速度 → **自动暂停**（速度≈0 且静止 N 秒）  
- [ ] UI 显示：海拔、坡度（可选）、状态图标  
- [ ] 日志输出 1Hz，便于与 GPS 对比  

### 6.3 里程碑 M2

**标准**：室内 UI 能看到实时气压海拔；晃动/静止能触发自动暂停逻辑。

---

## 7. 阶段 3：GNSS / L96（第 3～5 周）

### 7.1 接线（面包板）

| 信号 | 说明 |
|------|------|
| L96 VCC | **3.3V**（勿 5V） |
| GND | 共地 |
| L96 TX → MCU UART RX | 115200，后续改 10Hz |
| L96 RX ← MCU UART TX | **建议电平匹配**（L96 I/O 约 2.8V） |
| 天线 | **外置 FPC/Patch**，勿依赖模块 Chip 天线做性能评估 |

### 7.2 任务

- [ ] 解析 **NMEA**：`$GNRMC`、`$GNGGA`（时间、经纬度、速度、定位质量）  
- [ ] PMTK：波特率 **115200**、`PMTK220,100` **10Hz**、按需精简 NMEA 输出  
- [ ] 实现 **速度、距离、航向**（速度单位 km/h，节×1.852）  
- [ ] **GPS 校时** 写入片内 RTC（有定位时）  
- [ ] 简单 **轨迹缓存**（RAM 环缓冲，先不写 SD）  
- [ ] UI：GPS 状态、卫星数、速度、里程  
- [ ] 户外试骑 **1 次**，对比手机码表误差  

### 7.3 可选

- [ ] L96 **LOCUS** 记录 + 批量读取（低功耗备份轨迹，需移远解析代码）  
- [ ] V_BCKP 备份电容（热启动）— 面包板可焊 0.47～1F 超容测试  

### 7.4 里程碑 M3

**标准**：户外 3D 定位稳定；10Hz 刷新速度；轨迹在屏上可显示；里程与手机误差 &lt;5%（开阔地）。

---

## 8. 阶段 4：存储与骑行记录（第 5～7 周）

> **策略更新（2026-06）**：独立 **`gpx/` 组件**负责 GPX 编解码与批写记录；bicycle `DP_Recorder` 保持 X-TRACK 不变。详见 [ble/companion_recording.md](ble/companion_recording.md)。

### 8.1 任务

- [ ] **microSD**：FatFS，挂载 `/sd`  
- [ ] App 侧 **GPX 骑行记录**（geolocator + 流式写文件）  
- [ ] `ble_companion` Control/Status 与会话同步  
- [ ] （可选）码表 GNSS → App Track Point Notify  
- [ ] 历史记录列表在 **App**（文件名、日期、距离）  
- [ ] 配置项写入 SD 或 Flash（单位、轮径、记录间隔）  

### 8.2 固件分区概念

| 存储 | 内容 |
|------|------|
| 外置 Nor | 程序、UI 资源、字体 |
| SD | 地图瓦片、**导航 GPX**（App 下发）、可选本地备份 |

### 8.3 里程碑 M4

**标准**：App 完成一次骑行后生成可导入 Strava/高德的 GPX；码表未写 `/Track` 记录文件；路线 GPX 可通过 BLE FS 或 MTP 下发。

## 9. 阶段 5：地图（可选，第 7～10 周）

按需求二选一或分版本：

| 版本 | 内容 | 难度 |
|------|------|------|
| **V1.0** | 仅 **轨迹线** + 纯色底图 | 低（推荐先做） |
| **V1.1** | **离线栅格瓦片**（SD 目录 `/MAP/z/x/y.bin`） | 中 |
| **V1.2** | 路线导航、GPX 导入 | 中高 |

任务要点：

- [ ] 瓦片预处理工具链（桌面脚本 → RGB565 bin）  
- [ ] 按 GPS 坐标加载 3×3 / 5×5 窗口  
- [ ] 按键 **平移/缩放**（无触摸）  
- [ ] 评估 SD 容量与覆盖区域  

### 里程碑 M5

**标准**：V1.0 轨迹回放；或 V1.1 在户外可拖动查看预下载区域地图。

## 10. 阶段 6：BLE（第 8～10 周）

### 10.1 任务

- [ ] 熟悉 SDK **BLE** 例程（连接、GATT）  
- [ ] **CSCS**（踏频/速度传感器）或 **HRS**（心率带）二选一先做  
- [ ] UI 显示心率/踏频  
- [ ] （可选）与手机 **自定义 GATT** 同步骑行记录  

实现与双角色约束见 [ble/ble_sensor.md](ble/ble_sensor.md)；手机 Companion 见 [ble/README.md](ble/README.md)。  

### 10.2 里程碑 M6

**标准**：骑行中 BLE 传感器数据稳定显示 ≥30min。

---

## 11. 阶段 7：对齐量产电源 SF32LB527（第 10～12 周）

开发板为 JUD6 时，本阶段在 **新硬件或 LCD-1 充电路径** 上验证：

- [ ] `HAL_PMU_ChgInit`、充电电流、满电电压（4.2 / 4.35V）  
- [ ] VBAT **GPADC 电量** 与 UI 百分比  
- [ ] 低电量关机策略（&lt;3.2V 降功能，&lt;3.0V 保存关机）  
- [ ] 休眠电流目标：**背光关 + GPS standby + Flash 断电**  
- [ ] 评估是否增加 **SF30147**（Flash/背光负载开关）  

### 里程碑 M7

**标准**：电池供电续航粗测 ≥10h（MIP 中亮、GPS 10Hz、无 BLE）；充电 USB 正常。

## 14. 风险与对策

| 风险 | 对策 |
|------|------|
| L96 仅 2.8V UART 电平 | 预留分压/电平转换；先读 TX 再写 RX |
| 面包板 QSPI 屏不稳定 | 显示只用开发板 FPC，面包板仅 I2C/UART |
| JUD6 与 527 充电差异 | 阶段 7 专门对齐；前期不依赖片内充电 |
| MIP 户外看不清 | 早做户外 UI 对比度测试；背光 Boost 留余量 |
| 地图体量过大 | V1 只做轨迹；瓦片按城市分包 |
| SDK 学习曲线 | 先改例程再重写；锁定 SDK release 版本 |
